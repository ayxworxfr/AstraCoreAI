> 对标标准：Claude.ai / ChatGPT / Perplexity。布局契约优先于视觉装饰，不用任何 magic number。

## 4. 布局契约详解

### 4.1 GlobalHeader（三段式）

```
布局: flex-row, align-items: center, height: var(--header-height)
├─ HeaderLeft  [width: var(--header-side-width), flex-shrink: 0]
│  规则: Logo 图标 + 文字，overflow: hidden，不换行
├─ HeaderCenter [flex: 1, display: flex, justify-content: center]
│  规则: NavMenu 不得撑破容器；items 过多时改为 dropdown
└─ HeaderRight [width: var(--header-side-width), flex-shrink: 0, justify-content: flex-end]
   规则: 主题切换 + 未来可放用户头像；从右向左排列
```

### 4.2 Sidebar

```
布局: flex-column, width: var(--sidebar-width), flex-shrink: 0
├─ SidebarHeader [padding: 16px, flex-row, align-items: center]
│  规则: Logo icon + 折叠 toggle button；折叠时只显示 icon
├─ ActionArea [padding: 0 12px 10px]
│  - NewConversationButton: block, size=large
│  - SearchInput: width: 100%
├─ ConversationList [flex: 1, overflow: hidden]
│  规则: 内部滚动；分组后各组 header sticky
└─ 折叠状态
   - 宽度: 0（配合 CSS transition: width 0.2s）
   - 内容: visibility: hidden（保留 DOM，避免反复 mount）
```

### 4.3 聊天三栏布局契约（核心）

```
MessageRow [display: flex, width: 100%, margin-bottom: var(--msg-row-gap-y)]

├─ AIAvatarSlot [width: var(--avatar-slot-width), flex-shrink: 0, padding-right: var(--avatar-gap)]
│  - AI 消息: <Avatar size={32} icon={<RobotOutlined />} />
│  - 用户消息: 空 div（保持占位，宽度不变）
│  规则: 永远不允许消息气泡进入此区域

├─ ContentSlot [flex: 1, min-width: 0, display: flex, flex-direction: column]
│  - AI 消息: align-items: flex-start → 内容自然展开，max-width: 100%
│  - 用户消息: align-items: flex-end → 气泡最大宽度 80%（防止短消息撑满）
│  规则: 左边界不得超过 AIAvatarSlot 右边缘，右边界不得超过 UserAvatarSlot 左边缘

└─ UserAvatarSlot [width: var(--avatar-slot-width), flex-shrink: 0, padding-left: var(--avatar-gap)]
   - 用户消息: <Avatar size={32} icon={<UserOutlined />} />
   - AI 消息: 空 div（保持占位，宽度不变）
   规则: 永远不允许消息气泡进入此区域
```

> **为什么自定义 MessageRow 而非 Bubble.List 的 roles.avatar**：`Bubble` 组件只支持单侧头像，无法在消息行两端同时保留固定占位区域。当前用 `marginLeft/Right: 44` 的 workaround 依赖 `ant-bubble-content-wrapper` 内部实现，存在 antd/x 版本升级破坏的风险。专业做法是完全自定义 MessageRow，用 `Bubble` 只渲染内容（不传 avatar prop），头像区单独管理。

### 4.4 MessageListContainer 与 InputContainer 对齐

两者使用完全相同的 maxWidth 和 padding-x，保证消息列表左边界 = 输入框左边界：

```
MessageListContainer:
  max-width: var(--content-max-width); margin: 0 auto;
  padding: var(--msg-padding-y-top) var(--content-padding-x) var(--msg-padding-y-bottom)

InputContainer:
  max-width: var(--content-max-width); margin: 0 auto;
  padding: 0 var(--content-padding-x)
```

## 5. 视觉设计

### 5.1 主题系统

使用 antd 5 `ConfigProvider` + `theme.darkAlgorithm` 实现，所有组件自动跟随，无需手写 CSS 变量。

**主色调：** `#1677ff`（antd 默认蓝，与 Ant Design X 组件配合最佳）

**深色主题 token 定制：**
```typescript
{
  colorBgBase: '#0d1117',
  colorBgContainer: '#161b22',
  colorBorderSecondary: '#30363d',
}
```

**浅色主题 token 定制：**
```typescript
{
  colorBgBase: '#f5f7fa',
  colorBgContainer: '#ffffff',
  colorBorderSecondary: '#e8edf2',
}
```

主题偏好持久化到 `localStorage["astracore.settings.v1"]`，刷新后恢复。

### 5.2 消息气泡设计

- **用户消息**：主色蓝背景，右对齐，无头像（头像在 UserAvatarSlot）
- **AI 消息**：Surface 背景，左侧带 `[A]` 头像图标，内容区渲染 Markdown
- **思考与工具**：工具轮旁白展示为 thinking 区块，工具调用显示执行中/完成/失败状态
- **流式输出**：Bubble 内置 `loading` 状态与打字光标，SSE 订阅后台 Chat Run，结束时统一收敛状态
- **滚动条**：Chat 主区域使用简约自定义滚动条，按明暗主题适配，支持拖动和点击轨道平滑跳转

### 5.3 Welcome 空态

会话无消息时展示 Welcome 组件：

```

│                ✦  AstraCoreAI                               │
│           专业 AI 基础设施，开始你的对话                    │
│                                                             │
│   ┌──────────────┐  ┌──────────────┐  ┌──────────────┐    │
│   │ 你能做什么？ │  │ RAG 怎么用？ │  │ 工具调用示例 │    │
```

## 7. 状态管理

### 7.1 类型定义

```typescript
type ConversationMeta = {
  id: string              // UUID，同时作为后端 session_id
  title: string
  updatedAt: string
  lastMessagePreview: string
  messageCount: number
  pinned: boolean
  skillId?: string | null // undefined = 默认，'none' = 禁用，uuid = 指定 Skill
  modelId?: string | null // null/undefined = 后端默认
}

type ChatMessage = {
  id: string
  role: 'user' | 'assistant'
  content: string
  thinkingBlocks?: string[]
  toolActivity?: ToolActivity[]
  status: 'pending' | 'streaming' | 'done' | 'error'
  createdAt: string
}
```

### 7.2 chatStore


## 8. API 契约

### 8.1 Chat Run 流式（SSE）

```
POST /api/v1/chat/runs
Body: { message, session_id?, skill_id?, model_profile?, temperature?, enable_thinking?, thinking_budget?, enable_rag?, use_tools?, enable_web? }
Response: { run_id, session_id, status }

GET /api/v1/chat/runs/:run_id/stream
SSE 事件：
  event: run_state       data: { run_id, session_id, status, assistant_content, ... }
  event: message         data: { text }
  event: thinking_start / thinking / thinking_stop
  event: tool_start / tool_result
  event: done            data: {}
  event: error           data: { message }

GET  /api/v1/chat/sessions/:session_id/runs/active
POST /api/v1/chat/runs/:run_id/cancel
```

前端 SSE 处理流程：
1. 插入用户消息和 `status: 'streaming'` 的 assistant 占位消息
2. `POST /chat/runs` 创建后台 run，保存 `activeRunId`
3. 订阅 `/chat/runs/:run_id/stream`，以 `subscribedRunIds` 去重，同一个 run 只有一个 SSE 连接
4. `message` 事件追加到占位消息；thinking 事件写入 `thinkingBlocks`；tool 事件写入 `toolActivity`
5. 收到 `done` 后重新加载后端消息历史，以 DB 为准
6. 刷新或切换回会话时，通过 active run 接口恢复正在运行的生成任务
7. `run_state` 用于还原完整 UI 快照，清理乐观插入的临时消息

### 8.2 Session 记忆清理

```
DELETE /api/v1/chat/sessions/:session_id   → 204 No Content
```

删除或清空对话时 fire-and-forget 调用。

### 8.3 其他接口

```
POST /api/v1/rag/retrieve   Body: { query, top_k? }

GET    /api/v1/skills/
POST   /api/v1/skills/
PUT    /api/v1/skills/:id
DELETE /api/v1/skills/:id

GET /api/v1/settings/
PUT /api/v1/settings/

GET /api/v1/system/   → { llm: { profiles[] }, tavily_configured, mcp_servers[] }
```

## 9. 交互规则

### 9.1 会话管理

- 新建会话后自动切换为当前会话
- 首条用户消息自动设为会话标题（截断到 24 字）
- 重命名通过 Conversations 组件内联编辑（不用 `window.prompt`）
- 删除当前会话后自动切换到最近活跃会话；若无则新建空白会话
- 流式输出过程中允许刷新页面；刷新后重新订阅当前会话 active run
- 会话列表支持置顶和搜索过滤

### 9.2 流式输出

- 中断按钮调用后端 cancel 接口，真正取消后台 run
- SSE 订阅异常不等于生成失败；若后台 run 仍在运行，重新进入会话会恢复订阅
- 同一个 `run_id` 只能保留一个 SSE 订阅
- 工具调用中的中间轮文字只进入 thinking 区，不冒充最终答案

### 9.3 一致性保障

- 每条消息写入必须携带 `conversationId`
- 严禁将流式增量写入非当前激活会话
- run 恢复时使用固定消息 ID（如 `run-${run_id}`）替换旧的 streaming assistant，不为同一 run 追加第二个 assistant 气泡
- 任何异常结束都将 assistant 消息状态收敛到 `error` 或 `done`

## 10. 错误处理

| 场景 | 处理方式 |
|---|---|
| 网络请求失败 | 消息气泡显示错误态，提供重试 |
| SSE 订阅中断 | 重新查询 active run 并恢复订阅；只有 run 本身失败才展示错误 |
| localStorage 损坏 | 检测异常时自动清空并重置 |
| 后端 5xx | 统一错误提示，展示 `detail` 字段内容 |

## 11. 验收标准

- 双主题切换流畅，无组件主题不跟随问题
- 消息列表左边界 = 输入框左边界（用浏览器开发者工具量像素）
- AI 消息头像始终贴左，用户消息头像始终贴右，跨消息类型时占位存在
- 消息气泡在任何情况下不进入头像占位区（短消息/长消息/代码块/表格均验证）
- Header 三段在 1280px / 1440px / 1920px 下对齐正常，不挤压
- 窗口缩小至 900px 时，消息列表和输入框仍有 `content-padding-x` 的最小边距，不贴边
- 会话能力完整：新建、切换、重命名、删除、清空、刷新恢复
- 生成恢复：AI 回答过程中刷新页面后，后端 run 继续执行，前端回到会话可恢复订阅
- 多会话下不串消息，流式稳定，Markdown 正确渲染
