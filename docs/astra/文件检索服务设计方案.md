# 文件检索服务设计方案

## 1. 背景与定位

### 1.1 现状问题

当前 `src/astracore/mcp_servers/filesystem_server.py` 中的 `search_files` 工具存在以下问题：

```python
# 当前实现（filesystem_server.py:244-272）
async def search_files(pattern: str, path: str | None = None) -> str:
    for match in root.glob(pattern):    # ← 单线程 Python glob
        if _check_allowed_path(match):
            matches.append(str(match))
        if len(matches) >= 200:         # ← 硬编码 200 上限
            break
```

四个根本性缺陷：

| 缺陷 | 表现 | 后果 |
|------|------|------|
| 单线程 Python glob | `Path.glob('**/*.py')` 串行遍历 | 万级目录耗时数十秒 |
| 无 ignore 过滤 | 会扫描 `node_modules/`, `.venv/`, `__pycache__/`, `.git/` | 大量无关结果稀释信号 |
| 仅文件名匹配 | 不支持文件内容检索 | AI 需 glob + 逐个 read，本质方法错误 |
| 200 结果硬截断 | 大目录返回不全 | 结果不可信 |

### 1.2 定位

构建**通用文件检索服务**，定位为 AI Agent 调用的工具层基础设施：

- **服务对象**：MCP filesystem 工具集消费者（主要是 LLM tool loop）
- **数据范围**：用户授权的任意目录，**不限于代码项目**
- **检索模式**：实时检索（live search），**不引入 RAG / 向量索引 / 持久化倒排索引**
- **核心诉求**：在万级到百万级文件目录中，毫秒到秒级返回精确结果

### 1.3 不在此次范围（Non-Goals）

明确**不做**的事，避免 scope creep：

- ❌ 不做 RAG / embedding / 向量检索
- ❌ 不做持久化索引（ctags / tantivy / Elasticsearch）
- ❌ 不做 AST / 语义级搜索（ast-grep / Tree-sitter）
- ❌ 不做 LSP 集成（goto definition / references）
- ❌ 不做代码项目专属的智能（IDE 级特性）
- ❌ 不做跨机器分布式检索

> 这些能力强大但目标场景错位：用户检索的是任意文件夹，不一定是代码项目。索引方案的"维护成本 > 实时方案的查询成本"。

## 2. 设计原则

| 原则 | 含义 |
|------|------|
| **实时优于索引** | 借助 ripgrep 的工程红利，绝大多数场景实时扫描已足够快，避免引入索引一致性问题 |
| **过滤前置** | 在工具层而非 AI 层过滤垃圾结果（`.git/`、`node_modules/`），减少 AI 上下文消耗 |
| **路径动态白名单** | 默认拒绝未授权路径，但通过 HITL 让用户在会话内临时授权 |
| **结果可分页** | 不再硬截断，提供 offset/limit 让 AI 自主翻页 |
| **可观测** | 每次检索记录耗时、扫描文件数、匹配数、被忽略数 |

## 3. 引擎选型：ripgrep

### 3.1 为什么选 ripgrep

| 指标 | ripgrep | Python glob | GNU grep |
|------|---------|-------------|----------|
| 语言 | Rust | Python | C |
| 并行 | ✅ 多核 | ❌ | ❌ |
| `.gitignore` | ✅ 自动识别 | ❌ | ❌ |
| 内存映射 I/O | ✅ mmap | ❌ | 部分 |
| SIMD 加速 | ✅ | ❌ | ❌ |
| 测试基准 | 5-40x faster than GNU grep（官方 benchmark） | baseline 慢 | 中等 |

Claude Code 自身也以 ripgrep 为底层搜索引擎（Grep 工具），是经过工业级验证的选择。

### 3.2 安装策略

```text
检索 ripgrep 二进制顺序：
1. 系统 PATH 中的 rg                    ← 优先使用（用户已自带）
2. 项目 vendored 二进制（bin/rg.exe）   ← fallback
3. 启动失败提示安装                      ← 兜底
```

`pyproject.toml` 不强依赖 ripgrep，README 提示安装命令：

```bash
# Windows
winget install BurntSushi.ripgrep.MSVC
# macOS
brew install ripgrep
# Linux
apt install ripgrep
```

## 4. 工具集 API 设计

将原本一个 `search_files` 工具拆分为 **4 个职责清晰的工具**，全部通过 MCP filesystem server 暴露：

| 工具 | 替换/新增 | 职责 |
|------|----------|------|
| `find_files` | 替换 `search_files` | 按文件名 / glob 查找文件 |
| `grep_content` | 新增 | 按内容（regex）检索文件 |
| `read_file_range` | 增强 `read_file` | 按行范围读取，避免一次读太多 |
| `inspect_directory` | 新增 | 目录结构概览（文件类型分布、大小、深度） |

### 4.1 `find_files` — 文件名检索

```python
@mcp.tool(description="按 glob 模式查找文件名，自动遵循 .gitignore 与内置黑名单。")
async def find_files(
    pattern: str,                       # glob 或 regex（type 控制）
    path: str | None = None,
    *,
    type: Literal["glob", "regex"] = "glob",
    max_results: int = 100,
    offset: int = 0,
    include_hidden: bool = False,
    extra_excludes: list[str] | None = None,    # 单次查询追加 ignore
    follow_symlinks: bool = False,
) -> str:
    """返回格式：
    [stats] scanned=N matched=M ignored=K elapsed=XXms
    /path/to/file1
    /path/to/file2
    ...
    [pagination] offset=0 limit=100 has_more=true|false
    """
```

底层调用：

```bash
rg --files \
   --glob "<pattern>" \
   --max-count <max_results+offset> \
   [--hidden] [--no-ignore] [-L]
```

### 4.2 `grep_content` — 内容检索

```python
@mcp.tool(description="按正则在文件内容中检索，返回匹配行（含上下文）。")
async def grep_content(
    pattern: str,                        # ripgrep regex
    path: str | None = None,
    *,
    glob: str | None = None,             # 限定文件名 glob
    file_type: str | None = None,        # ripgrep --type：py / js / md / ...
    case_sensitive: bool = False,
    context_before: int = 0,
    context_after: int = 0,
    max_matches: int = 50,
    max_matches_per_file: int = 10,
    offset: int = 0,
    multiline: bool = False,
    output_mode: Literal["content", "files_with_matches", "count"] = "content",
) -> str:
    """返回格式（content 模式）：
    [stats] files_scanned=N files_matched=M total_matches=K elapsed=XXms
    === /path/to/file.py ===
       12: matched line
       13- context after
    ...
    [pagination] offset=0 limit=50 has_more=true|false
    """
```

底层调用：

```bash
rg --json \
   -e "<pattern>" \
   [-g "<glob>"] [--type <type>] \
   [-i] [-A <n>] [-B <n>] \
   --max-count <max_matches_per_file> \
   [-U --multiline-dotall] \
   [-l | -c]
```

使用 `--json` 输出便于结构化解析、计算分页与统计。

### 4.3 `read_file_range` — 范围读取

```python
@mcp.tool(description="读取文件指定行范围，避免一次性加载大文件。")
async def read_file_range(
    path: str,
    *,
    offset: int = 1,            # 1-based 起始行
    limit: int = 200,           # 读取行数
    encoding: str = "utf-8",
) -> str:
    """返回格式：
    [file] /path/to/file.py (total_lines=1234 size=45KB)
    [range] lines 1-200
       1: ...
       2: ...
    ...
    [pagination] next_offset=201 has_more=true
    """
```

> 与现有 `read_file` 共存：`read_file` 读全文（≤8000 字符截断），`read_file_range` 用于大文件分页。

### 4.4 `inspect_directory` — 结构概览

```python
@mcp.tool(description="目录结构与文件分布概览，用于决定下一步如何检索。")
async def inspect_directory(
    path: str,
    *,
    max_depth: int = 3,
    top_n_by_size: int = 10,
    show_file_types: bool = True,
) -> str:
    """返回格式：
    [path] /path/to/dir (total_files=12345 total_size=234MB)

    [file types]
      .py    : 1234 files (45MB)
      .md    : 234 files  (3MB)
      .json  : 89 files   (1MB)

    [largest files (top 10)]
      234MB  /path/to/data.bin
       45MB  /path/to/dump.sql

    [structure (depth=3)]
      src/
        astracore/
          modules/   (45 subdirs, 234 files)
          ...

    [excluded]
      .git/ (1234 files), node_modules/ (45678 files)
    """
```

这是给 AI 的"目录画像"，避免 AI 盲目 `find_files **/*` 撞大运。

## 5. 三层 Ignore 策略

### 5.1 设计目标

孤立目录（非 git 仓库）和代码项目共存，必须无脑工作。

### 5.2 三层叠加

```text
┌─────────────────────────────────────────┐
│ Layer 1: 自动检测 .gitignore             │ 仓库根存在 .git 时自动启用
├─────────────────────────────────────────┤
│ Layer 2: 内置硬编码黑名单                │ 任何场景都生效
├─────────────────────────────────────────┤
│ Layer 3: config.yaml extra_excludes     │ 用户配置叠加
├─────────────────────────────────────────┤
│ Per-query: extra_excludes 参数           │ 单次查询追加
└─────────────────────────────────────────┘
```

### 5.3 Layer 1：自动 `.gitignore`

ripgrep 默认行为 — 检测到 `.git/` 自动遵循 `.gitignore`。

### 5.4 Layer 2：内置硬编码黑名单

无论是否 git 项目，永远忽略：

```python
_BUILTIN_IGNORES = [
    # VCS
    ".git", ".hg", ".svn",
    # 依赖
    "node_modules", "bower_components", "vendor",
    # Python
    "__pycache__", ".venv", "venv", ".tox", ".pytest_cache", ".mypy_cache",
    "*.pyc", "*.pyo",
    # JS/TS
    "dist", "build", ".next", ".nuxt", ".cache", ".turbo",
    # 编辑器
    ".idea", ".vscode", ".vs",
    # macOS / Windows
    ".DS_Store", "Thumbs.db",
    # 大文件
    "*.log", "*.sqlite", "*.sqlite3", "*.db",
    "*.exe", "*.dll", "*.so", "*.dylib",
    "*.zip", "*.tar", "*.gz", "*.7z", "*.rar",
    "*.iso", "*.dmg",
    "*.mp4", "*.mov", "*.avi", "*.mkv",
    "*.pdf",   # AI 大概率读不了，需要时单独 read
]
```

> 重要：用户可通过 `extra_excludes` 反向开启某项（如 `*.pdf` 需要纳入时显式声明）。

### 5.5 Layer 3：`config.yaml` 配置

```yaml
filesystem:
  search:
    extra_excludes:
      - "*.bin"
      - "tmp/"
      - "snapshots/"
    follow_symlinks: false
    case_sensitive_default: false
```

### 5.6 Per-query override

每个工具调用都接受 `extra_excludes: list[str]` 参数，单次叠加。

## 6. 安全护栏

### 6.1 三道防线

```text
┌────────────────────────────────────────────────┐
│ Defense 1: 绝对黑名单（永不可访问）             │
├────────────────────────────────────────────────┤
│ Defense 2: 路径白名单（启动配置 allow_paths）   │
├────────────────────────────────────────────────┤
│ Defense 3: HITL 动态白名单（会话内临时授权）    │
└────────────────────────────────────────────────┘
```

### 6.2 Defense 1：绝对黑名单

不论是否被授权，永远拒绝：

```python
_ABSOLUTE_DENYLIST = [
    # *nix 系统目录
    "/etc", "/root", "/sys", "/proc", "/dev", "/boot",
    "/var/log", "/var/lib", "~/.ssh", "~/.aws", "~/.gnupg",
    # Windows 系统目录
    "C:/Windows", "C:/Program Files", "C:/ProgramData",
    "C:/Users/*/AppData",
    # 通用敏感
    "**/.ssh/**", "**/.aws/**", "**/.gnupg/**",
    "**/.kube/**", "**/.docker/config.json",
]
```

### 6.3 Defense 2：启动白名单

`config.yaml mcp.servers[type=filesystem].paths` 列出允许的根。该机制已存在。

### 6.4 Defense 3：HITL 动态白名单（核心新增）

#### 6.4.1 触发条件

工具调用时，目标路径**不在**启动白名单内 → 触发 HITL 审批：

```text
AI 调用 find_files(path="D:/other_project")
    ↓
工具层检查：D:/other_project 是否在 allowed_paths？
    ├─ 是 → 直接放行
    └─ 否 → 检查是否在 _ABSOLUTE_DENYLIST？
            ├─ 是 → 立即拒绝（不触发 HITL）
            └─ 否 → 触发 HITL 审批
```

#### 6.4.2 审批流程

借用现有 `hitl_callback` 机制，复用 `ask_user` 的实现路径：

```python
# 在工具实现内
async def find_files(pattern: str, path: str, ..., _context: dict):
    if not _check_allowed_path(path):
        if _is_absolute_denied(path):
            return f"[拒绝] 路径在绝对黑名单内: {path}"

        # 触发 HITL
        approved = await _context["hitl_callback"](
            kind="path_approval",
            payload={
                "path": path,
                "tool": "find_files",
                "reason": f"AI 想要在 {path} 中搜索 '{pattern}'",
            },
            timeout=300,
        )
        if not approved:
            return f"[拒绝] 用户未批准访问: {path}"

        # 临时加入 session 白名单
        _session_allowed_paths(_context["session_id"]).add(Path(path).resolve())

    # 正常执行
    ...
```

#### 6.4.3 白名单生命周期

| 范围 | 持久度 |
|------|--------|
| 启动白名单（`config.yaml`） | 永久 |
| HITL 动态白名单 | **本次 session 内有效**，session 结束失效 |
| 用户拒绝 | 本次 session 内同路径不再触发审批，直接拒绝 |

#### 6.4.4 前端 UI 提示

复用现有 HITL 审批弹窗，附加路径预览：

```text
┌─ 路径访问请求 ─────────────────────────┐
│ AI 想要使用工具 find_files 访问：       │
│   D:/other_project                    │
│                                       │
│ 原因：搜索 '*.py' 文件                  │
│                                       │
│ 风险提示：                              │
│ • 该路径不在启动配置的允许列表内          │
│ • 批准后本次会话内 AI 可重复访问该路径    │
│                                       │
│ [拒绝]              [批准本次会话]      │
└───────────────────────────────────────┘
```

### 6.5 subprocess 调用安全

调用 ripgrep 时**严禁 `shell=True`**：

```python
# ✅ 正确：argv 数组，参数作为独立元素，shell 不参与解析
proc = await asyncio.create_subprocess_exec(
    "rg", "--files", "--glob", pattern, str(path),
    stdout=asyncio.subprocess.PIPE,
    stderr=asyncio.subprocess.PIPE,
)

# ❌ 错误：拼接字符串 + shell=True 会被注入
# subprocess.run(f"rg --files {pattern} {path}", shell=True)
```

## 7. 敏感内容处理（宽松模式）

### 7.1 策略

**只警告，不替换内容**：

- 检测到疑似敏感模式（密钥、token、密码）时，在输出**追加 warning 行**
- **不**对匹配内容做脱敏 / 替换 / 截断
- 用户看到完整内容，自行判断

### 7.2 检测规则

```python
_SENSITIVE_PATTERNS = [
    (r"AKIA[0-9A-Z]{16}", "AWS Access Key"),
    (r"sk-[a-zA-Z0-9]{32,}", "OpenAI/Anthropic API key style"),
    (r"ghp_[a-zA-Z0-9]{36}", "GitHub Personal Access Token"),
    (r"-----BEGIN (RSA |EC |OPENSSH |DSA )?PRIVATE KEY-----", "Private key"),
    (r"password\s*[:=]\s*['\"]?[^\s'\"]{6,}", "Password literal"),
    (r"[A-Za-z0-9+/]{40,}={0,2}", "Possible base64-encoded secret"),
]
```

### 7.3 输出示例

```text
[stats] files_scanned=12 files_matched=1 total_matches=1
=== /path/to/.env ===
   3: ANTHROPIC_API_KEY=sk-ant-api03-xxxxx-xxxxx-xxxxx

⚠ [sensitive content warning]
  Detected patterns: "Anthropic API key style" in /path/to/.env:3
  内容已完整返回，请确认是否应排除该路径或文件。
  Consider: 添加 .gitignore / extra_excludes
```

## 8. 性能护栏（大目录三档保护）

### 8.1 三档分级

通过 `inspect_directory` 或检索开始前 `rg --files | wc -l` 估算：

| 量级 | 行为 |
|------|------|
| < 10k 文件 | 直接执行 |
| 10k ~ 1M 文件 | 执行 + 警告 + 强制 `max_results` |
| > 1M 文件 | **拒绝**，返回建议（缩小 path / 加 glob / 用 inspect_directory 先画像） |

### 8.2 实现

```python
async def _estimate_size(path: Path) -> int:
    """快速估算目录文件数，使用 rg --files | head -n 1000001 不阻塞。"""
    proc = await asyncio.create_subprocess_exec(
        "rg", "--files", str(path),
        stdout=asyncio.subprocess.PIPE,
    )
    count = 0
    async for _ in proc.stdout:
        count += 1
        if count > 1_000_001:
            proc.kill()
            return count
    return count


async def find_files(...):
    size = await _estimate_size(root)
    if size > 1_000_000:
        return (
            f"[拒绝] 目录文件数 > 1M（估算 {size}+）。\n"
            f"建议：\n"
            f"  1. 缩小 path 到子目录\n"
            f"  2. 使用 inspect_directory 先了解结构\n"
            f"  3. 在 extra_excludes 中加入大子目录"
        )
    if size > 10_000:
        warning = f"⚠ 大目录（{size} 文件），执行中..."
    ...
```

### 8.3 超时

工具层强制超时（默认 30s），超时即中断 subprocess 并返回部分结果：

```python
try:
    stdout, stderr = await asyncio.wait_for(
        proc.communicate(),
        timeout=30,
    )
except asyncio.TimeoutError:
    proc.kill()
    return f"[超时] 检索 > 30s，已中断。请缩小范围。"
```

### 11.2 测试覆盖

每个工具至少 3 类测试：

1. **Happy path**：正常 glob / regex / 范围参数
2. **边界**：空目录 / 单文件 / 大目录 / 不存在路径 / 二进制文件
3. **安全**：路径越权 / 绝对黑名单命中 / HITL 拒绝 / 敏感内容触发

### 11.3 兼容性

旧 `search_files` 工具**直接替换为 `find_files`**，不保留兼容层（用户明确指示不需向前兼容）。

## 12. 验证标准

实施完成后，下列查询必须满足：

| 场景 | 期望 |
|------|------|
| 在 10k 文件目录搜索 `*.py` | < 500ms |
| 在 100k 文件目录搜索 `*.md` | < 3s |
| 在 100k 代码目录内容检索 regex | < 5s |
| 自动忽略 `node_modules/` `.git/` | 不出现在结果中 |
| 访问未授权路径 | 触发 HITL，批准后可访问，会话结束失效 |

| 检索到 API key | 完整内容返回 + warning 行 |
| 检索 2M 文件目录 | 立即拒绝并给出建议 |
| `--shell=True` 注入测试 | 工具调用安全（argv 数组隔离） |
