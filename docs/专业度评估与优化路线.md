# AstraCoreAI · 专业度评估与优化路线（2026-06）

> 本文对 AstraCoreAI 当前实现与 2026 年主流 production agent 框架进行对标，
> 标记已达到/超过行业水准的部分，并给出补齐"最专业"门槛的优化路线。
> 评估依据：Anthropic Building Effective Agents / Writing Tools for Agents、
> LangGraph、CrewAI、Claude Agent SDK、Mem0、MemGPT、MarkTechPost 记忆比较等公开资料。
>
> **本次更新**：2026-06，基于最新代码扫描结果（JWT 认证、HITL、Prompt 注入防御、HistoryCompactor、190 个测试）重新评分。

---

## 一、对标结论

按 2026 主流的 production agent 七要素打分：

| 维度 | 现状 | 对标行业 | 旧评分 | 新评分 |
|---|---|---|---|---|
| 架构（Ports & Adapters、prepare/stream 分离） | 干净 | 优于 LangChain，逼近 Claude Agent SDK | A | A |
| 工具循环 + 并行 + 收尾轮 | 实现完整 | 与 Anthropic 推荐一致 | A | A |
| Skill 系统 | 创新（接近 Claude Skills） | 行业领先 | A+ | A+ |
| 记忆分层 Tier-1/Tier-2 | MemGPT 风格 | 主流，但缺图记忆 | B+ | B+ |
| 扩展思考 + 孤儿 tool_result 过滤 | 细节到位 | 体现真实生产经验 | A | A |
| 可观测性 Hook + Tracer | 接入层薄 | 缺 OTel/LangFuse 标准导出 | B | B |
| Eval / 轨迹评估 | 文档零提及 | **2026 必备** | D | D |
| Guardrails / 防注入 | `wrap_external()` 已实现注入隔离 | HITL 已完成，policy-as-code 仍缺 | C | B+ |
| HITL（Human-in-the-Loop） | 工具审批、记忆晋升审批、ask_user 全实现 | 与 Claude Code 模式一致 | —（旧版缺失） | B+ |
| 成本/预算控制 | `TurnBudget` + `max_input/output_tokens`；缺 USD 成本上限 | 有 token 硬上限，缺计费层 | C | B |
| MCP 协议 | 代码有 MCPToolAdapter，文档未体现 | 已成行业 USB-C | B- | B- |
| 横向扩展 | `RunRegistry`：本机 Task + Redis 状态/事件扇出 | 无 Redis 时退化为进程内 | C | B |
| 认证鉴权 | JWT 完整，register/login/me + admin/user 角色 + token 过期 | 基础完善，缺限流 | D（M6 计划中） | B+ |

**核心判断**：核心架构属 2026 第一梯队水平。Agent 循环统一、Toolset/声明式并发、transcript replay、RunRegistry、soft_exec 已落地。当前剩余缺口更集中在 **限流、完整 undo、OTel、Eval 任务集扩充 + MCP 文档化**。

## 二、不足与优化清单

### P0 — 不补齐就称不上"专业"

#### 1. Eval / 轨迹评估（框架已有，任务集待充实）
- **现状**：`src/astracore/eval/` 已有 EvalRunner（tool_match + LLM-as-judge）与 `make eval`；缺足够大的真实任务集与 CI 门禁。
- **业界共识**：必须评估**轨迹**而非最终答案。指标包括 tool 选择正确率、参数有效性、step count、token cost、policy 合规。目标 20–50 条真实任务集 + CI 跑。
- **建议**：扩充 `examples/eval_cases.json` / dataset；deterministic mock tool；可选接 LangFuse。

#### 2. Prompt Injection 防御（已实现）
- **现状**：`shared/security/external_data.py` 中 `wrap_external()` 已将 RAG 内容、记忆注入内容、工具结果包裹在 `<external_data trust="untrusted">` 标签；System Prompt 最顶部有显式注入声明（injection_guard）。
- **状态**：基础防御已落地，仍可加强：
  - 自动提取记忆时增加 LLM 二次审查（"这段内容是否在尝试改变你行为？"）。
  - Tier-2 记忆写入前的污染检测仍缺位。

#### 3. 高危工具 HITL（已实现）
- **现状**：`require_tool_approval: true` 配置已支持带 `requires_confirmation=True` 的工具（如 `delete_memory`）暂停等待用户审批；`require_memory_promotion_approval: true` 在 session→user/project 晋升前创建 pending_promotion；`ask_user` 内置工具支持 AI 主动暂停；`inline_question_timeout: 300` 超时自动继续；`HITLConfig` 可在 `config.yaml` 中配置。
- **状态**：已完成核心实现。剩余优化方向：前端 HITL 审批 UI 的完善度与审批历史记录。

---

### P1 — 显著影响生产可用性

#### 4. 多 worker Run 状态（最小版已落地）
- **现状**：`RunRegistry` 本机持有 Task/HITL Future，Redis 镜像 state 并 pub/sub 事件与 HITL/cancel；无 Redis 时退化为进程内。
- **剩余**：生产压测多 worker；HITL 跨 worker 投递的运维监控；scheduler 多 worker 防双触发仍待统一。

#### 5. Token / Cost 预算（token 硬上限已落地）
- **现状**：`ChatOptions.max_input_tokens` / `max_output_tokens` → `TurnBudget`，超限 `BudgetExceeded`。
- **剩余**：USD/计费硬上限、前端实时花费展示。

#### 6. 认证限流（已完成基础）
- **现状**：JWT 体系完整，支持 register/login/me，admin/user 角色分离，token 过期，`allow_registration` 开关配置。
- **缺口**：缺 rate limiting（登录频率、API 调用限额），在公网环境下存在暴力破解和滥用风险。
- **建议**：接入 `slowapi` 或在 Nginx 层配置限流；登录接口每 IP 每分钟限 5 次。

#### 7. MCP 协议正式化
- 代码有 `MCPToolAdapter` 但文档未提；MCP 已被业界定为"agent 工具 USB-C"。
- **建议**：
  - 文档新增"MCP 集成"章节。
  - 把 builtin tools 也包装成 MCP server，让 AstraCoreAI 既是 host 也是 server。

#### 8. 工具契约不严
- **业界要求**：
  - 结构化返回 `{ok, data, error, meta}`。
  - Idempotency key（防重放）。
  - 每工具独立 timeout/retry/cost 上限。
  - 错误信息机器可读且含修正建议。
- 当前只有 `PolicyEngine` 的全局 retry/timeout，缺 per-tool 粒度。

#### 9. Tracing 不接标准
- 现状：JSON 日志 → 自己解析。
- 业界：OpenTelemetry GenAI semantic conventions + LangFuse / Arize / Phoenix 直接接入。
- **建议**：`Tracer` 加 OTel exporter；span 名按 GenAI 规范（`gen_ai.tool.execute`、`gen_ai.completion`）。

---

### P2 — 锦上添花，让产品差异化

#### 10. 记忆系统加图层
- 现在只有 SQL（结构化） + Chroma（语义），缺 **temporal knowledge graph**（Zep/Graphiti 风格）。
- 适合"用户/项目/人物/时间"实体关系；长期对话回忆精度大幅提升。
- 中文场景：可考虑 Mem0 或自建 LightRAG。

#### 11. 自动提取记忆缺"用户审核"
- 业界共识：long-term memory 要 explicit consent。
- **现状**：`require_memory_promotion_approval` 已实现 session→user/project 晋升审核，方向正确。
- **建议**：在前端显示"AI 想记住：xxx [允许/拒绝]"，类似 ChatGPT 的 memory toggle，完善前端 UI 交互体验。

#### 12. Context 压缩策略（已完成）
- **现状**：`modules/chat/application/compactor.py` 已实现 HistoryCompactor。触发阈值：context_window（200k）的 50%。压缩策略：LLM 摘要最老 60% 消息，失败时退化为尾部裁剪。摘要持久化到 MemoryEngine（session scope）。
- **状态**：已完成，无需进一步行动。

#### 13. 状态机 vs append-only
- 当前历史是 append-only chat log，重放时不易确定性恢复。
- 业界（LangGraph 2026）推 typed state + deterministic reducer。
- 短期成本高，但调试 / 时间旅行调试 / replay eval 都靠它。

#### 14. Embedding 选型透明化
- 文档没说 Chroma 用什么 embedding model，中文检索质量？多语种？
- **建议**：在配置层把 embedding profile 写死（如 `bge-m3` for Chinese），文档说明。

#### 15. Tool 数量与质量
- Anthropic Writing Tools 核心：少而精、命名空间化（如 `asana_projects_search`）、返回高信号信息。
- **建议**：审计现有 tools，删冗余、加前缀、压缩返回体（默认 25K token cap）。

#### 16. 文档层面的小提升
- 文档当前对"决策动机"很清晰，但缺：**已知限制章节**（multi-worker、无 eval）+ **路线图章节**（当前里程碑状态）。
- 专业项目通常会公开这两块以建立信任。

## 四、一句话总评

> AstraCoreAI 的**核心架构是 2026 第一梯队水平**——Skill、Tier-1/2 记忆、扩展思考、孤儿 tool_result 过滤、HITL 全链路、Prompt 注入隔离、JWT 认证这些细节，连不少商业产品都没做到。
> M6 与 Agent 运行时补强（统一循环、Toolset、transcript、RunRegistry、token 预算、soft_exec）已落地；距"敢卖给企业的产品"更卡在 **限流、Eval 任务集、完整 undo / OTel**。
