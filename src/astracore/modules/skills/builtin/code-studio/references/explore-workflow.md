# /explore 工作流

专用于代码探索和信息收集，**不做任何代码修改**。  
适合：理解某个模块工作机制、定位某功能实现位置、分析变更影响范围、为 /plan 收集前置信息。

---

## 执行步骤

### 步骤 1：解析探索目标

从用户输入提取探索目标，识别目标类型：

| 目标类型 | 示例输入 | 探索策略 |
|---|---|---|
| 模块/功能名 | `/explore 认证流程` | 搜索关键词 → 定位入口文件 → 展开调用链 |
| 文件路径 | `/explore src/auth/` | 直接读取目录结构 → 关键文件内容 |
| 问题/疑惑 | `/explore 为什么登录会超时` | 先搜索相关关键词 → 定位相关逻辑 |
| 变更影响 | `/explore 修改 User 模型的影响` | 搜索引用 → 列出依赖链 |

### 步骤 2：制定探索计划

列出计划读取的文件（**最多 15 个**），展示给用户确认：

```
准备探索以下文件：
1. src/auth/router.py — 认证路由入口
2. src/auth/service.py — 认证业务逻辑
3. src/auth/models.py — 数据模型
...（共 N 个文件）

确认开始探索？(直接回复确认，或调整范围)
```

- 超过 15 个文件 → 先列出最核心的 10 个，说明理由，其余列为"备选"
- 不确定在哪里时 → 先搜索关键词定位（grep / 文件搜索），再确定读取列表

### 步骤 3：执行探索

按确认列表逐一读取文件，重点关注：

- **入口**：功能从哪里开始（路由 / 触发点 / 主函数）
- **调用链**：关键函数/类如何串联
- **数据流**：输入从哪来、经过哪些处理、输出到哪去
- **依赖**：引用了哪些外部模块 / 服务 / 配置

读取过程中如发现需要读额外文件，先告知用户再读（不得静默扩展范围）。

### 步骤 4：整理并输出探索报告

按以下格式输出，不是流水账，是结构化总结：

---

## 探索报告模板

```markdown
## 探索报告：<目标名称>

**探索时间**: YYYY-MM-DD  
**探索范围**: [列出实际读取的文件]

### 核心发现

[入口在哪 / 主要组件是什么 / 关键路径描述]

### 调用链 / 数据流

[关键流程的文字描述，如适用]

```
[可选：用简单 ASCII 图描述流程]
A → B → C → D
```

### 关键文件

| 文件 | 职责 |
|---|---|
| `path/to/file` | 描述 |

### 注意事项

[边界条件 / 未解之谜 / 潜在风险 / 值得关注的 TODO]
```

---

### 步骤 5：询问是否归档

输出报告后询问：

```
探索完成。是否将报告保存到 .claude/astra/explore/YYYY-MM-DD-<slug>.md？
保存后可在 /plan 时引用。(y/n)
```

- 用户确认 → 写入文件
- 用户拒绝 → 不写入，报告仅存于当前对话

---

## 检查门

- 目标**过于模糊**（如 `/explore 代码`）→ 反问"你想了解哪个模块或功能？"，获取具体目标后再开始
- 探索中发现文件**不存在** → 告知用户，询问是否有其他路径，不得假设文件内容
- 发现**敏感信息**（密钥 / 密码）→ 在报告中用 `[已隐藏]` 替代，不输出原文
